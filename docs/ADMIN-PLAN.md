# Следующий этап — управление мастерской

Запрос пользователя: хозяйке нужен интерфейс, в котором можно менять мастер-классы, цены и расписание без редактирования файлов. Реализация подтверждена и выполнена в этапе 9. Итог: [STAGE-9.md](STAGE-9.md); инструкция: [ADMIN.md](ADMIN.md). Ниже сохранён согласованный состав работ.

## Интерфейс

Отдельный адрес `/admin/`, один владелец, защищённый вход. Без регистрации посетителей и личных кабинетов. Стили, формы и навигация согласованы с визуальным языком сайта; таблицы на телефоне превращаются в читаемые списки.

1. **Программы.** Создание и редактирование названия, направления, описаний, результата, цены, длительности, возраста, вместимости, преподавателя, материалов и условий получения работы. Выбор обложки и галереи из подготовленной локальной медиатеки. Публикация и архивирование. Опубликованная программа должна иметь все обязательные сведения.
2. **Расписание.** Список по датам, создание сеанса выбранной программы, изменение даты и времени по Туле, вместимости, закрытие записи и отмена. Создание повторяющихся занятий на выбранные дни с предварительным просмотром. Проверка пересечений для одной небольшой мастерской.
3. **Записи.** Брони конкретного сеанса: номер, статус, количество участников, сумма, контакты и комментарий. Отмена отдельной брони с подтверждением. Фильтрация по дате и статусу; закрытые данные доступны только после входа.

## Правила изменений

- Программу с сеансами и бронями можно архивировать, а не физически удалять. История и доступ к старой персональной ссылке сохраняются.
- Новая цена действует для новых записей; подтверждённая бронь сохраняет свою сумму. Перед записью сервер продолжает проверять актуальную цену.
- Вместимость нельзя уменьшить ниже уже занятого числа мест.
- Перенос и отмена сеанса с бронями показывают число затронутых участников и требуют отдельного подтверждения. При отмене сеанс закрывается, связанные действующие брони получают согласованный статус.
- Интерфейс явно показывает, что участникам нужно сообщить об изменении. Автоматические уведомления о переносе или отмене не считаются отправленными без реализованной и проверенной доставки. Текущее подтверждение через Telegram не означает подписку всех участников на уведомления.
- Ошибки ввода, сохранения и конфликт изменений показываются без потери заполненных полей.

## Изменения архитектуры

Frontend-стек сохраняется: HTML/Nunjucks, Stylus, БЭМ, jQuery, ES-модули и Vite. Сервер остаётся Node.js/Express, база — SQLite.

Для редактирования без пересборки единственный рабочий источник каталога переносится в SQLite. Текущие JSON используются как исходное демонстрационное наполнение; повторный импорт не перезаписывает правки хозяйки. Существующие сеансы, брони, суммы и токены сохраняются миграцией.

Пользовательские страницы формируются сервером из общего набора Nunjucks-шаблонов и актуальных данных базы с прежними полноценными адресами. Vite собирает Stylus и ES-модули; сервер подключает готовые ресурсы через manifest. Так изменение цены или появление программы сразу отражается в каталоге, детальной странице и записи. Ручная пересборка для каждой правки не нужна.

Пароль хранится как стойкий хеш, сеансы входа — на сервере. Cookie входа недоступна JavaScript; на HTTPS включается Secure. Нужны защита изменяющих запросов, лимит попыток входа, выход и срок действия сессии. Учетные данные и списки участников не попадают в публичную сборку, URL или журналы. Первичная настройка владельца документируется отдельно, без пароля по умолчанию.

## Приёмка

В браузере проверить вход/выход, создание и архивирование программы, смену цены без изменения старой брони, добавление/перенос/отмену сеанса, ограничение вместимости и просмотр записей. Автоматически проверить запрет доступа без входа, истечение сессии, защиту изменения данных, конфликт сохранений, миграцию и сохранение изменений после перезапуска. После завершения расширить и повторить production-проверку.
