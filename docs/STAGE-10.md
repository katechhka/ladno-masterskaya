20 октября 2026 года. По запросу пользователя сначала исправлен футер, затем выполнена расширенная проверка production-запуска через локальный HTTPS-прокси.

Скриншоты на 1920, 1440, 768 и 360 px сохранены в `screenshots/stage-10/`; компьютерная и мобильная версии просмотрены. Проверены отсутствие горизонтального переполнения, одинаковое оформление ссылок/кнопки, открытие уведомления и возврат клавиатурного фокуса.

## Проверка через HTTPS

```sh
npm run build
npm run acceptance:check
```

Команда создаёт временную SQLite-базу и каталог фотографий внутри `.cache/tests/acceptance-*`, наполняет их относительно текущей даты, запускает настоящий `server/index.mjs` в отдельном процессе с `NODE_ENV=production`, точным HTTPS `PUBLIC_ORIGIN` и `TRUST_PROXY=1`. Перед ним работает локальный HTTPS-прокси, который самостоятельно выставляет заголовки доверенного проксирования. Установленные ограничения запросов и защитные заголовки не отключаются.

Временный самоподписанный сертификат и ключ создаются стандартным `node:crypto`; подпись и SAN проверяются через `X509Certificate`. Системное хранилище сертификатов не меняется. Только тестовый браузер разрешает самоподписанный сертификат. После завершения процессы, сертификат, ключ, база и загруженные тестовые файлы удаляются. Проверено настоящее соединение TLS 1.3, а не только наличие HTTPS в адресной строке.

Результаты:

1. Футер корректен на четырёх ширинах; cookie-уведомление открывается, закрывается и возвращает фокус.
2. Вход хозяйки выдаёт `__Host-ladno_admin` с Secure, HttpOnly и SameSite=Strict. Изменяющий запрос без CSRF и запрос с чужим Origin получают 403.
3. Цена и загруженная через админку фотография сохраняются после остановки и повторного запуска Node.js. Сеанс входа восстанавливается из постоянной базы. Новая публичная цена доступна без пересборки, старая бронь сохраняет прежнюю сумму.
4. PDF всех трёх документов доступны через HTTPS и содержат корректную сигнатуру PDF. `.env`, файл доступа хозяйки, база и Vite manifest публично не выдаются.
5. Выход отзывает доступ: закрытый API возвращает 401.
6. На ширине 360 px оформлена новая бронь на двух участников по новой цене. После перезапуска подтверждение сохраняется. Отзыв согласия удаляет контакты и освобождает ровно два места; исходная отдельная бронь продолжает занимать своё место.
7. В проверенных браузерных сценариях нет ошибок JavaScript и консоли. Тестовый пароль, токен исходной брони и контакты не появились в журнале сервера.

Отчёт: [acceptance-check.json](acceptance-check.json). Скриншоты: `screenshots/stage-10/`. Рабочая база, доступ хозяйки и фотографии пользователя не менялись; настоящие сообщения не отправлялись.

## Общая регрессия

`npm run test:all` успешно завершён: production-сборка, все 52 серверных теста и пять браузерных наборов прошли. Наборы проверяют бронирование, пограничные состояния, телефон/Telegram, админку, фотографии/cookie/согласия. Итог этого прогона: [automated-check.json](automated-check.json). Скрипт останавливается при любой неуспешной проверке.

## Границы результата

Проверена локальная схема «HTTPS-прокси → production Node.js → постоянная тестовая SQLite и файлы». Это не развёртывание на публичном хостинге и не проверка доверенного сертификата конкретного домена. Реальный сервер, DNS, публичная цепочка сертификатов, автоматический запуск и расписание резервного копирования ещё должны быть настроены при развёртывании. Проверки Safari, Firefox и физических устройств не выполнялись.
