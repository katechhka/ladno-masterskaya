# Этап 4 — бронирование

Реализован полный путь: программа → сеанс → участники → имя, обязательный телефон, email и согласия → проверка → подтверждение → персональная страница → подтверждённая отмена. Оплата только на месте после занятия; демонстрационные записи ничего не оплачивают. Письма и SMS не отправляются.

Табы «Глина / Краска / Отпечаток» выровнены в общую сетку с одинаковой высотой. Смещение неактивных кнопок убрано, переключатель отделён от наклонной фотографии. Исправление действует также на `/design/`.

## Сервер

- Express API подключён к Vite в разработке и preview. `npm start` обслуживает `dist/` и API одним Node.js-процессом.
- Главная, расписание, выбор даты и форма читают актуальные `/api/catalog` и `/api/sessions`. Статический снимок больше не используется интерфейсом для доступности.
- `POST /api/bookings`: строгая Zod-валидация, проверка будущей даты, цены и количества мест. Телефон обязателен и нормализуется в международный формат.
- Сохранение брони и идемпотентного ключа выполняется в `BEGIN IMMEDIATE`. SQLite-триггеры дополнительно защищают вместимость. Подтверждённая цена фиксируется в копейках.
- Ключ запроса связан с хешем нормализованного тела. Повтор возвращает ту же бронь; изменение тела отклоняется. При потере ответа интерфейс повторяет неизменённый запрос.
- Браузер создаёт 256-битный токен через Web Crypto; в базе хранится только SHA-256. Персональная ссылка содержит токен после `#`, он не передаётся в адресной строке HTTP-запросов. Запросы управления используют заголовок Authorization.
- `GET /api/bookings/me` и `POST /api/bookings/me/cancel` требуют токен. Номер брони не открывает контакты. Отмена повторяется безопасно, место вычисляется из подтверждённых броней.
- Нет публичных списков участников. JSON ограничен 16 КБ; включены лимиты запросов, проверка Origin для изменений и запрет кеширования API. Контакты и токены не записываются в серверные логи.

## Проверки

`npm test`: 20 тестов контента, базы, расчётов, валидации телефона, повторов, одновременных HTTP-запросов, отмены и повторного открытия SQLite/HTTP-сервера.

`npm run booking:check`: установленный Chrome, отдельная тестовая база в памяти, собранный сайт и настоящий API. На 1440, 768 и 360 px проверены ровные табы, обязательный телефон, запись группы из двух человек, проверка суммы, персональная ссылка, обновление страницы, подтверждение отмены и освобождение мест. Отдельно воспроизведена потеря ответа после сохранения и повтор без дубля. Отчёт: `booking-check.json`; 18 скриншотов: `screenshots/stage-4/`. Данные на скриншотах вымышленные, тестовая база уничтожается после проверки.

`npm run pages:check`: регрессия страниц с новым API; каталог, галереи, расписание, состояния ошибок, URL и 404. Скрипт обновлён под действующую форму с телефоном.

## Границы этапа

Проверено обслуживание production-сборки Express-сервером в локальном браузерном тесте. Полная проверка реального развёртывания, расширенная матрица пограничных сценариев, отдельные этапы автоматических и визуальных проверок остаются по плану. Публичного развёртывания нет; почта, SMS, оплата и личный кабинет не подключаются.

После этапа работа останавливается до подтверждения перехода к этапу 5.
