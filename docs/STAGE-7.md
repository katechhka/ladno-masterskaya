# Этап 7 — визуальная проверка

Завершён 20 октября 2026 года. Сохранён утверждённый дизайн второй версии: кобальтовая афиша, фотоколлаж, шрифты Unbounded и Onest.

## Исправления

- На планшете форма записи перестроена в одну основную колонку. Поля контактов получили достаточную ширину: маска `+7 (900) 000-00-00` видна целиком.
- На телефоне фильтры каталога расположены последовательно, в том же порядке, что и переход клавишей Tab. Поля каталога, расписания и выбора сеанса используют текст не меньше 16 px.
- Уменьшены промежутки первого экрана на телефоне. На проверенных размерах 360×800 и 390×844 основная кнопка целиком помещается в первом экране.
- Для элементов фильтра добавлены отдельные БЭМ-классы; поведение и URL-параметры сохранены.

## Браузерная проверка

Настоящий установленный Chrome, автоматизация Playwright, размеры окна: 1920×1080, 1440×1000, 768×1024, 390×844 и 360×800. Это эмуляция размеров окна, не проверка на физических телефонах или планшетах.

Сделаны 103 скриншота: главная, каталог, детальная страница, расписание, запись, управление бронью, правила, сведения о данных и 404. Дополнительно сняты переключённые табы, клавиатурный фокус, увеличенная галерея, мобильный выбор сеанса, пустой каталог, ошибки формы, подключение Telegram и подтверждение отмены. Основные композиции, изображения, форма на планшете и мобильные состояния просмотрены визуально.

Результат `npm run visual:check`:

- Нет горизонтального переполнения на проверенных страницах; заголовки всех 14 программ проверены на пяти ширинах.
- Все видимые изображения загружены; используется локальный Onest.
- Три таба главной имеют одинаковую высоту и выровнены.
- Клавиша Tab открывает ссылку перехода к содержимому.
- Маска телефона помещается в поле на всех пяти размерах.
- Закреплённая мобильная панель не перекрывает кнопку подтверждения выбора сеанса на 768, 390 и 360 px.
- В отчёте нет нарушений измеренного контраста основного текста: пороги 4,5:1 для обычного и 3:1 для крупного текста.
- Нет ошибок JavaScript и неожиданных HTTP-ошибок при этом прогоне.

Отчёт: [visual-check.json](visual-check.json). Скриншоты: `screenshots/stage-7/`. Проверка использует отдельную SQLite-базу в памяти и вымышленные контакты. Рабочие брони не менялись; настоящие сообщения не отправлялись.

## Повторные функциональные проверки

Успешно выполнены после правок:

```sh
npm run build
npm run visual:check
npm run pages:check
npm run booking:check
npm run notifications:check
```

`pages:check`: 15 сценариев и 16 проверок страниц по размерам. `booking:check`: запись группы и отмена на 1440, 768 и 360 px. `notifications:check`: ввод, вставка и редактирование телефона, интерфейс Telegram и защита от повторов на 1440 и 360 px, без настоящих сообщений.

## Ограничения и следующий этап

Safari, Firefox и физические устройства в этом этапе не проверялись. Вычисление контраста охватывает текст в `main` на обычных цветных фонах, не заменяет полный аудит доступности и не оценивает текст поверх растровых изображений или псевдоэлементы. Проверка выполнена с уменьшенным движением; ручная оценка анимаций на физических устройствах не проводилась.

Сборка уже используется для изолированных браузерных проверок. Отдельная итоговая проверка production-запуска, конфигурации и полного сценария относится к этапу 8 и ожидает подтверждения пользователя.
