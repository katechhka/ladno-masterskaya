# Подтверждение записи в Telegram

**Облачное размещение:** бот переключён на защищённый webhook опубликованного сайта. Локальный long polling с тем же ботом запускать не нужно. Актуальная инструкция — [CLOUD.md](CLOUD.md). Ниже сохранены устройство и проверки локального подключения; прежние ссылки относятся к локальной базе.

По запросу пользователя добавлена бесплатная интеграция Telegram Bot API. SMS и почта не подключаются. Сам сайт и бот по-прежнему обозначают мастерскую как вымышленную.

## Подключение

1. Откройте [BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`, задайте имя и уникальный username бота. Для этого проекта используйте отдельного бота.
2. Скопируйте `.env.example` в `.env`, если файла ещё нет. Добавьте локально:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_BOT_USERNAME=username_бота_без_символа_собаки
TELEGRAM_PROXY_URL=
```

Токен не публикуется, не добавляется в Git и не должен иметь префикс `VITE_`. Не присылайте его в чат. Для API сайта и бота используйте одинаковый `DATABASE_PATH`.

3. Перезапустите `npm run dev` и в отдельном терминале запустите:

```sh
npm run telegram:bot
```

Для собранного сайта используйте `npm run build` и `npm start`; бот запускается второй командой в отдельном процессе. Схема данных обновляется автоматически без удаления броней. В production нужны постоянный диск SQLite и два управляемых процесса: один HTTP-сервер и один обработчик Telegram.

Обработчик использует long polling; локальный сервер доступен боту без публичного домена и туннеля. Нужен исходящий HTTPS-доступ к `api.telegram.org`. Запускайте один обработчик на бота. У него не должно быть ранее установленного webhook другого приложения. Настройка не удаляет чужие webhook автоматически. При старте проверяется соответствие токена username бота.

Если прямой доступ к Telegram завершается таймаутом, задайте `TELEGRAM_PROXY_URL` с адресом своего HTTP(S)-прокси. Прокси применяется только к запросам бота; проверка TLS остаётся включённой. На текущем компьютере проверка `getMe` прошла через уже настроенный системный прокси Windows, его адрес добавлен только в локальный `.env`. Зависимость `undici` обеспечивает HTTPS-туннель. В исходниках и примере `.env` адрес конкретного прокси отсутствует.

## Путь пользователя

1. Оформить запись с обязательным телефоном и email.
2. На персональной странице нажать «Получить в Telegram», затем «Открыть Telegram».
3. В личном чате бота нажать «Старт».
4. Получить сообщение с номером брони, занятием, датой и временем по Туле, количеством участников и суммой.

Если Telegram открыл уже существующий чат без запуска команды по ссылке, нажмите на сайте «Скопировать команду для бота» и отправьте её целиком в этот чат. При недоступном буфере обмена появится поле для ручного копирования. Номер брони вместо команды не подходит.

По одному номеру телефона Telegram не отправляет сообщение. Пользователь сам открывает бота. При возвращении на страницу статус проверяется повторно.

## Защита и статусы

- Ссылка содержит отдельный случайный 256-битный токен на 15 минут. Это не токен управления бронью; отменить запись через него нельзя. В SQLite хранится только SHA-256.
- Создать ссылку и проверить статус можно только с токеном персональной страницы. Списков участников нет.
- Подтверждение отправляется только в личный чат. Телефон, имя, email, комментарий и персональная ссылка управления в сообщение не включаются.
- Транзакционное присвоение статуса `sending` исключает параллельную повторную отправку. Статус `sent` устанавливается только после успешного ответа Telegram с `message_id`.
- Явный отказ API даёт статус `failed` и возможность создать новую ссылку. Неизвестный результат после таймаута или прерывания даёт `unknown`: автоматической повторной отправки нет. Проверьте чат. Если владелец убедился, что сообщения нет, он может перевести соответствующую запись `telegram_confirmations` в `failed` через SQLite, после чего пользователь сможет повторить попытку.
- Offset обновлений сохраняется для конкретного бота. Повтор обновления не создаёт второе подтверждение.
- Ошибка Telegram не отменяет бронь. Подтверждение и персональная ссылка остаются на сайте.

Без токена и username сайт явно сообщает, что бот не подключён. Никакого утверждения об отправленном сообщении нет. Реальная доставка требует вашего бота и запущенного обработчика.

В таблице `telegram_confirmations` хранятся статус, chat_id, message_id, хеш одноразового токена и время. Резервная копия SQLite включает их; правила доступа и хранения такие же, как у демонстрационных броней. Тело сообщения и секреты в журналы не записываются.

## Проверки

```sh
npm test
npm run build
npm run notifications:check
```

Автоматические проверки Telegram используют локальную подмену транспорта и не отправляют настоящие сообщения. Проверяются одноразовая ссылка, истечение срока, чужой токен, групповой чат, параллельный `/start`, отказ и неизвестный результат. Браузерный тест проверяет маску, редактирование, длинную вставку и интерфейс Telegram на 1440 и 360 px. Отчёт: `docs/phone-telegram-check.json`, в нём явно указаны `simulatedTelegramTransport: true` и `realMessagesSent: 0`.

2026-10-19 выполнена отдельная реальная проверка: пользователь подключил своего бота, оформил тестовую бронь и отправил команду из персональной страницы. Сообщение получено пользователем; в рабочей базе зафиксирован `sent`, обработчик зарегистрировал личную команду с кодом. Прямой переход сначала не запустил подтверждение; ручная команда из добавленной кнопки успешно активировала ссылку. Токен отсутствует в клиентской сборке. Обработчик оставлен запущенным локально.

Для повторной проверки оформите запись, откройте бота по выданной ссылке и нажмите «Старт» либо отправьте скопированную команду. После перезапуска компьютера снова запустите `npm run telegram:bot` вместе с сервером сайта.

Первичные источники: [создание бота](https://core.telegram.org/bots/tutorial#obtain-your-bot-token), [deep linking](https://core.telegram.org/bots/features#deep-linking), [Bot API](https://core.telegram.org/bots/api).
