# Этап 6 — автоматические тесты

Добавлены шесть межпроцессных интеграционных тестов. Они запускают настоящий `server/index.mjs` отдельными процессами Node.js с общим временным файлом SQLite. Стартовое время тестового сеанса — через три дня от запуска; фиксированных календарных дат нет. Рабочая база не используется.

## Новые проверки

1. Четыре процесса и 48 разных запросов на три места: ровно три ответа 201, остальные 45 — отказ по вместимости. В базе три участника, свободных мест ноль.
2. Четыре процесса и 16 повторов с одним ключом: одна новая бронь, 15 повторных ответов с тем же номером, один ключ в базе.
3. Два одновременных запроса с одним ключом и разным телом: одна бронь, второй запрос получает `REQUEST_CHANGED`.
4. Двенадцать параллельных отмен: одна фактическая отмена. Повтор исходного запроса возвращает отменённую запись. Новая бронь занимает освобождённые места; повтор старой отмены их не освобождает.
5. Принудительная остановка процесса после подтверждения и запуск нового Node.js: сохраняются номер, контакты, цена, токен и результат идемпотентного запроса. После отмены и ещё одного перезапуска статус остаётся отменённым.
6. Ошибка SQLite после вставки брони, на шаге сохранения ключа: API отвечает 503, вся транзакция откатывается, места сохраняются. После устранения тестового сбоя тот же запрос успешно создаёт одну бронь.

## Команды

```sh
npm test
npm run test:process
npm run test:all
```

`npm test` включает все 26 тестов контента, дат, базы, сервисов, HTTP и отдельных процессов. `test:process` запускает только шесть новых проверок.

`test:all` последовательно выполняет production-сборку, `npm test`, `booking:check` и `functional:check`. При первой неуспешной команде прогон останавливается с ошибкой. Результаты и длительности команд записываются в `docs/automated-check.json`. Браузерные отчёты: `booking-check.json` и `functional-check.json`.

Сквозные проверки запускают установленный Chrome и настоящий API: основной путь записи/отмены на 1440, 768 и 360 px, а также 15 пограничных сценариев. Сценарии повторно выполняются при полном прогоне.

## Изоляция и ограничения

Каждый межпроцессный тест создаёт отдельный каталог внутри `.cache/tests/`. Процессы слушают свободные локальные порты; в тестовые переменные окружения явно передаётся путь отдельной базы. После проверки процессы завершаются, а каталог удаляется с проверкой границ пути. Тестовые контакты вымышленные, журналы не содержат тел запросов или токенов.

Проверка четырьмя процессами подтверждает ограничения общей SQLite-базы. Для рабочего развёртывания по-прежнему предусмотрен один Node.js-процесс с постоянным локальным диском. Оценка предельной нагрузки и тестирование удалённого хостинга не проводились. Итоговая визуальная проверка и проверка развёртывания остаются этапами 7 и 8.

Полный `test:all` выполнен успешно: все четыре команды завершились с кодом 0. В отчёте `automated-check.json` указано `passed: true`. Этап завершён; переход к этапу 7 ожидает подтверждения пользователя.
