# Публикация на Vercel

**Архив подготовки. Впоследствии сайт опубликован:** https://ladno-masterskaya.vercel.app/. Актуальная инструкция — [CLOUD.md](CLOUD.md). Ниже сохранён статус до переноса сервера, он не описывает текущее размещение.

## Текущее состояние

По запросу пользователя выбран Vercel вместо подготовленного ранее Linux-сервера. Проверен существующий вход CLI в аккаунт `ekalininaaa-5066`, команда `portfolio-63cd`, где находится отдельный проект `letters-and-stars`. Этот проект не изменялся.

Создан новый проект `ladno-masterskaya`, текущая папка связана с ним через закрытый `.vercel/project.json`. Сайт пока **не развёрнут**, публичный адрес работающей мастерской не заявляется. Vercel создал локальный `.env.local` с временными служебными настройками; он исключён из публикации и Git. Файл `.env.example` остаётся доступным как безопасный пример.

Добавлен `.vercelignore`: рабочая SQLite-база, фотографии хозяйки из storage, резервные копии, файл пароля, локальные секреты, тестовые данные и скриншоты не отправляются вместе с исходниками. Перенос рабочей базы или секретов из `.env` в облако не выполнялся. На опубликованном демо следует использовать отдельные вымышленные данные.

## Почему требуется адаптация

Текущий Node.js-сервер использует постоянные локальные SQLite и UPLOADS_DIR, а Telegram работает отдельным long polling процессом. [Файловая система Vercel Functions доступна только для чтения, кроме временного /tmp](https://vercel.com/docs/functions/runtimes); он не заменяет постоянное хранилище. Поэтому статическая загрузка dist или перенос SQLite в /tmp не дают работающей постоянной записи.

Для этого размещения выбрана отдельная облачная SQLite-совместимая база Turso Cloud на бесплатном плане Starter ($0/месяц), регион dub1, через Vercel Marketplace. Доступ к ней требует асинхронного libSQL-клиента и адаптации серверных сервисов с сохранением транзакций, вместимости, идемпотентности и защиты входа. Frontend остаётся HTML/Stylus/jQuery/Vite, его дизайн менять не требуется.

Собственные фотографии потребуют постоянного объектного хранилища; возможность и условия его подключения проверяются после разблокирования базы. Локальный цикл Telegram необходимо заменить HTTPS-webhook с секретом и защитой от повторных обновлений. До успешной облачной проверки не переключайте работающего локального бота на новый webhook.

Платные планы и платные дополнения не подключались. Создание базы пока не завершено.

## Обязательное действие владельца аккаунта

Команда подключения базы вернула `action_required`, причину `integration_terms_acceptance_required` и `userActionRequired: true`. Vercel требует принять условия сервиса в браузере; автоматическая команда не может завершить этот шаг.

Откройте [подтверждение подключения Turso Cloud](https://vercel.com/portfolio-63cd/~/integrations/accept-terms/tursocloud?source=cli) в своём аккаунте Vercel. Проверьте условия сервиса и подтвердите их, если они подходят. Настройку платного тарифа не выбирайте. После этого можно повторить создание:

```sh
vercel integration add tursocloud --name ladno-db --plan starter --metadata region=dub1 --environment production --no-env-pull
```

Условия, предоставленные самой командой: [Vercel Marketplace addendum](https://vercel.com/legal/integration-marketplace-end-users-addendum), [Turso terms](https://turso.tech/terms-of-use), [Turso privacy](https://turso.tech/privacy-policy). Токены и пароли не нужно присылать в чат.

## Что остаётся до публикации

1. После подтверждения условий завершить создание отдельной базы и проверить фактически выданные настройки без вывода секретов.
2. Адаптировать сервер под удалённые транзакции, постоянное хранилище фотографий и Telegram webhook; сохранить локальный запуск и согласованное поведение. Подготовить облачное наполнение и отдельный доступ хозяйки.
3. Выполнить тесты конкурентных записей, повторов, отмены, входа и фотографий на облачном варианте. Настроить соответствующие ему копии/восстановление: существующие backup:create/backup:restore предназначены для локальной файловой SQLite и не являются готовой системой копирования Turso.
4. Развернуть проект Vercel, проверить HTTPS, прямые внутренние адреса, бронирование и сохранность после нового релиза, админку и Telegram. Только после проверки передать публичную ссылку.

Обычная публикация только витрины не заменяет эти шаги. Ранее выполненные локальные 56 тестов и HTTPS-проверки остаются действительными для прежнего серверного варианта; совместимость с Vercel ими ещё не подтверждена.
