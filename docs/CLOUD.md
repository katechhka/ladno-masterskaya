# Опубликованная версия «Ладно»

Сайт: **https://ladno-masterskaya.vercel.app/**. Админка: **https://ladno-masterskaya.vercel.app/admin/**.

Отдельный проект `portfolio-63cd/ladno-masterskaya` размещён в существующем аккаунте Vercel. Другие проекты не менялись. Frontend сохранён: HTML, Stylus, jQuery, ES-модули, Vite, Nunjucks и БЭМ. Node.js закреплён на ветке 22 начиная с 22.12; локальные проверки — 22.21.0.

## Доступ хозяйки

Для облачной базы создан отдельный владелец `owner`. Пароль находится **только локально** в `storage/cloud-admin-access.txt`, исключён из Git и загрузки в Vercel. Сохраните его в менеджере паролей, не публикуйте и не пересылайте файл. Локальный `/admin/` имеет другой доступ и другую базу. Команда `admin:setup` управляет локальным владельцем, не облачным.

Хозяйка работает через браузер по [ADMIN.md](ADMIN.md): программы, цены, фото, архив, даты/повторения, места, записи и отмены. Изменения сохраняются без сборки. При утрате облачного доступа разработчик с доступом к Turso задаёт новый scrypt-хеш владельца и отзывает admin_sessions; публичного восстановления по email нет. ADMIN_INITIAL_HASH используется только при первом создании отсутствующего владельца, не меняет пароль существующего.

## Постоянные данные

| Данные | Хранилище |
| --- | --- |
| Программы, цены, сеансы, брони, согласия, владелец и входы | Turso Cloud, отдельная база ladno-db |
| Свои фотографии хозяйки | Vercel Blob, отдельное публичное хранилище ladno-photos |
| Исходные сгенерированные фото, шрифты, PDF и ресурсы | Статические файлы релиза |
| Секреты базы, Blob, бота и служебных запросов | Защищённые переменные Production в Vercel |

Функции, база и Blob настроены на dub1 — [Дублин, Ирландия](https://vercel.com/docs/regions). Сборочная машина может находиться в другом регионе; файлы доставляются глобальной CDN. Это демопроект для вымышленных контактов. Политика и согласие обновлены с учётом размещения и технических ограничителей, редакция 2026-10-20-v2. Для реальных услуг остаются вопросы из [LEGAL.md](LEGAL.md).

Локальная база и фотографии пользователя не переносились: создано отдельное облачное демонаполнение из 14 программ и шести недель относительно даты наполнения. Повторное наполнение не удаляет брони и не сдвигает календарь. Новые даты добавляются в админке.

## Сервер

api/index.mjs — Express-приложение как Vercel Function. server/db/turso.mjs использует асинхронный libSQL-клиент. Общие сервисы через flow обрабатывают обычные локальные результаты синхронно, обещания Turso — асинхронно, сохраняя одни правила записи. Транзакции имеют отдельный контекст AsyncLocalStorage: запросы одной брони не попадают в чужую транзакцию. Цена, места, запись и ключ повтора сохраняются атомарно; вместимость дополнительно защищена триггерами.

Начальный каталог и сеансы создаются пакетами. HTML формируется из актуальной базы; статические index.html удаляются из облачной сборки, чтобы CDN не подменяла правки хозяйки старым каталогом. Ограничители используют общую таблицу request_limits: хеш технического идентификатора адреса, счётчик и конец окна. Ежедневная очистка удаляет просроченные окна. В карточке брони IP не сохраняется; технические журналы Vercel существуют отдельно.

Большие фотографии до 10 МБ уменьшаются в браузере перед отправкой, чтобы соблюсти [лимит запроса Vercel Functions](https://vercel.com/docs/functions/limitations). Сервер повторно проверяет файл, удаляет EXIF, создаёт WebP/AVIF и сохраняет производные в Blob. Маршрут /media/upload-… выдаёт их с того же адреса сайта. Подписи и галерея находятся в Turso.

## Telegram

Бот переключён на защищённый https://ladno-masterskaya.vercel.app/api/telegram/webhook. Проверяется случайный secret_token; посторонний запрос получает 403. Подтверждение отмечается отправленным только после успешного sendMessage. Повторы команды не дублируют сообщение, неясный результат остаётся unknown.

Посетитель нажимает «Получить в Telegram», открывает бота и нажимает «Старт» либо отправляет скопированную команду. Доставка не происходит по номеру телефона. Для облачных записей локальный telegram:bot не нужен: webhook и getUpdates несовместимы. Старые ссылки из локальной базы не переносят бронь в облако.

Проверены настройка webhook, отсутствие ожидающих обновлений при подключении, ответ с правильным секретом без отправки сообщения и отказ с неправильным. Реальная доставка из новой облачной записи требует действия пользователя; настоящее сообщение на этом этапе не отправлялось. Ранее пользователь подтверждал доставку локального варианта.

## Очистка и копии

Vercel Cron ежедневно в 00:15 UTC вызывает /api/maintenance с CRON_SECRET: очищает контакты после 90 дней, просроченные ограничители и давно прерванные отправки. Защищённый вызов проверен вручную. Локальный компьютер не требуется. Оповещения о сбое задачи не подключены.

```sh
npm run cloud:backup
```

Команда читает секрет из закрытого .env.cloud-secrets, получает согласованный снимок через /api/backup в read-транзакции и скачивает неизменяемые фотографии Blob. Старые входы хозяйки и счётчики запросов не включаются. В BACKUP_DIR создаётся ladno-backup-v1 с SQLite, фото и SHA-256; промежуточный закрытый снимок остаётся в .cache/backups. Не публикуйте копии: они содержат контакты и хеши доступа. Защищайте и шифруйте их при переносе, удаляйте также промежуточные снимки; для демо ограничьте хранение семью днями.

Автоматическое регулярное копирование, перенос на другой носитель и удаление старых копий не подключены. Cron очищает данные, а не создаёт копии. Лимит экспорта — 3 МБ JSON; при превышении нужен экспорт через Turso Dashboard с отдельным сохранением фото.

Восстановление по [BACKUP.md](BACKUP.md) проверено в новый локальный каталог: каталог, бронь, персональный токен, статус и фото сохранились. Оно не заменяет опубликованную базу. Для восстановления в облаке остановите приём записей, сохраните текущее состояние, подготовьте отдельную целевую базу, импортируйте проверенную копию средствами Turso/разработчика, перенесите или перепривяжите фото, затем переключите Production-подключение. Сверьте отмены и отзывы после даты копии. Удаление/замена рабочей базы и изменение тарифов автоматически не выполняются и требуют отдельного решения владельца.

## Повторная публикация

Папка связана с проектом через закрытый .vercel/project.json. При установленной авторизованной Vercel CLI:

```sh
vercel deploy --prod --yes
```

vercel.json задаёт dub1, функцию до 60 секунд, npm ci --include=dev, сборку npm run build:vercel и dist. Сборочная SQLite создаётся отдельно в .cache и не заменяет Turso. .vercelignore исключает storage, секреты, копии, большие оригиналы фото, тесты и документы. Подготовленные публичные изображения входят в релиз. Исходники хранятся в Git отдельно от рабочих данных. Автоматическое развёртывание из GitHub не подключено; релизы отправляются CLI.

TURSO_DATABASE_URL, TURSO_AUTH_TOKEN и BLOB_READ_WRITE_TOKEN выданы сервисами. PUBLIC_ORIGIN равен основному HTTPS-адресу, TRUST_PROXY=1. Секреты Telegram, webhook и cron хранятся на сервере. Пример без значений — .env.example; секретам не нужен префикс VITE_. Изменение переменных требует нового релиза. Не заменяйте .env.vercel на локальный .env и не переносите production-подключение в клиентский код.

- cloud:backup и пробное локальное восстановление выполнены. Контакты и секреты в отчёты не выводились.
- [automated-check.json](automated-check.json): полный локальный прогон — сборка, 60 тестов и пять браузерных наборов. После уточнения документов успешно пересозданы PDF и повторён privacy:check на 1440 и 360 px. Тестовые фотографии остались в медиатеке как сгенерированные изображения; удаления не выполнялись. Safari, Firefox и физические устройства не проверялись. Пользовательский домен не подключён, используется vercel.app с HTTPS. Бесплатные сервисы имеют квоты; платные планы не подключались.
